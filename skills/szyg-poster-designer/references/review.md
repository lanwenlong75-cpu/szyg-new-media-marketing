# 复核真实成品

先按用途判断，再看视觉：

- 倒计时：时间和事件是不是一眼就看见，数字/截止时间/时区是否正确，系列节奏是否清楚。
- 产品：主体或价值是否抓住目光，消费者能否看出适合谁、得到什么、如何了解，正文有没有挤压主体。
- 案例：证据是否可读、可判断，前后是不是同口径，结论是否越过证据，是否泄露不该公开的信息。

课程、活动及其他长图先对照当前文案逐组核对：主题、顺序、说明点数和必要条件是否齐全。先看开头能否识别主题与价值，再看详情是否容易找，结尾是否自然承接下一步。课程的天数、场次与点数按该项目确认值检查，不沿用别的课程数字。

局部修改后也查完整原区域，特别是末尾信息组；新增价格区不代表上方课纲自然保留。对照独立文案核对日期、价格、地点及入口。OCR只负责提示哪里可能漏字或误识，粗糙字体中的数字和相似字要回到图中确认；不要因OCR没识别就盲目重生图。

需要减少人工漏查时，可运行`scripts/check_poster_text.py --expected <文字清单JSON> --observed <OCR-JSON或文本> --out <核对结果JSON>`。输入格式见[文字清单辅助核对](text-coverage-check.md)。脚本对照当前文字列出命中、近似和未见项，不判定审美、扫码、图中真实缺失或用户认可。

另按本次公司／项目模板检查主题色继承：换风格后品牌主色是否仍承担主要识别，是否误用了参考图或另一品牌主色。允许中性色、留白与素材自然色辅助；不以必须铺满主色来损伤阅读。记录模板与风格版本，不能用配置通过代替实际看图。

再查看原尺寸与手机预览：字体是否适合主题、主次是否明确、段落和对齐是否有逻辑、照片裁切是否自然、空白是否有目的、色彩是否服务内容、行动是否自然收尾。不能把“字没有错”写成“设计没有问题”。

问题记录用可修改的描述，例如“标题和副标题同样重，先减副标题字重”“人物头部顶到边，扩上方空间”“案例截图缩后读不出证据，放大证据并减少装饰”。不要只写“更高级一点”。

先按真实参考校准字形、图文比例和空间，再组织文案与整张生图。检查模型最终画出的文字，不能沿用浏览器文字溢出检查或可编辑文字的结论。技术通过不能替代主视觉、阅读和身份核对。

每次交付标明：技术检查是否通过、哪些关键事实已核、已做哪些视觉检查、用户是否审过。设计师判断与用户偏好是两种记录，不给自己的图打满分后宣布用户认可。

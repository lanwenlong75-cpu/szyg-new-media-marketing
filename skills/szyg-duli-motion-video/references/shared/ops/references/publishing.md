# 发布与回读

查询、上传、草稿、发布走官方yxer CLI。先yxer --version、doctor，再读取CLI同步的yixiaoer/SKILL.md、共享规则、执行协议和对应业务域。缺规则时yxer skill sync --global，按CLI帮助确认同步位置。CLI升级后以当前字段和流程为准，不凭旧记忆拼payload，不绕过CLI调用私有API。

本包不重新分发蚁小二的闭源程序及未声明开放许可的完整规则；用户调用总Skill，由助手加载官方依赖。

核对编号、提交版本、画幅、字幕、绑定的真实PNG封面、文案、目标账号、平台、通道和时间。封面草稿不代表平台已采用。使用官方prepare/form/schema取得字段，上传资源使用返回值，动态集合/话题/商品等用真实查询结果。唯一合适账号可自动选择并说明，多候选按官方流程消歧。

**视频正式提交前的必经检查**：读取[视频与封面对应核验](publication-asset-match.md)，逐条完成内容与画面对应复核，并用`scripts/publication_assets.py check --root ROOT --manifest 核验清单.json --output 核验结果.json`核验视频、封面、上传响应和最终payload的绑定。只在对应核验、validate及dry-run均通过，且所绑定文件与payload摘要仍一致时提交；任一项失败就停在准备阶段。此项是助手的内部责任，已有明确发布授权时不重复询问用户。

同一payload、同一通道完成validate → publish --dry-run → 已授权范围内publish。用户具体授权明确就继续；只有准备发布时先完成文案、封面、payload、校验和预览，再请确认具体安排。工作台同步只读查询，不发布、不重试、不改期。

CLI接收任务后把真实taskSetId、videoId、提交file、sha256、平台、账号和计划时间写入来源JSON，再执行：

```text
python SKILL_DIR/scripts/ops.py bind-publication --root ROOT --file 来源JSON
python SKILL_DIR/scripts/ops.py sync --root ROOT
```

登记来源不是成功发布。成功回执才记已发布；到点无成功回执为到点待核验。失败与重试留明细，恢复前先核对已有任务以免重复发布。只有完整查询和用户确认发布范围后，缺记录才可归未发布。

指标按发布编号关联。视频号编号不同，需要正文、账号、时间、提交版本等证据形成唯一对应并留依据；标题相似或播放相同不足以关联。未关联账号作品不能推断其他平台未发布；用户历史确认与当前回执冲突保留两份证据。

封面画面优先取同版无字幕母版的干净帧，检查人物表情、构图和标题位置；原画面已有文字时避免重复叠加。需要保留选择时，在运营工作台/数据/封面素材/来源记录.json按videoId登记binding（当前主版media）、sourceMedia（已核对的无字幕源路径/大小/modifiedNs）、frameSeconds。来源必须实际存在且版本对应，文件变化后重新核对；不要凭名称猜母版。编辑器图片URL绑定实际取帧文件版本，保存后检查导出的PNG和卡片缩略图。

更换主版后重新核对封面绑定。仅改独立字幕层且封面底图、标题和内容仍适配时，经来源与取帧证据核对可以沿用PNG，新增绑定本版的记录并注明原封面编号及沿用理由，旧记录保留。换镜头、剪切或内容后重新检查对应时点和文案，不把旧media字段直接改成新版来冒充来源验收；先完成再登记，避免卡片缺封面或错误沿用。

未发布成片默认同时完成封面，不等用户发现空白再补。先按逐字稿提炼核心问题或收益，标题不虚构数据与效果；用真实底图、清楚的短标题和合适留白完成独立PNG。用户采用抖音作品页样式时按3:4、1080×1440交付。横屏录屏可以完整保留示范画面，把标题放在独立空间；不裁掉演示重点来强行铺满。原片仅做预览封面，不能因此改成待发布或已发布。

批量操作编辑器时等待对应编号与底图加载完成，再设置标题、标题显示开关和构图。保存前回读这些实际值，保存后打开真实PNG与缩略图检查文字完整、英文不被拆散、没有字幕叠在标题背后、人物和示范画面可辨认。仅有保存回执或PNG文件不代表设计完成。保留可编辑布局参数、底图来源、时点及版本绑定；进入发布准备时使用实际核对过的PNG。

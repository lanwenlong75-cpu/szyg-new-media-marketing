# 视频与封面对应核验

每次视频发布、重新预约或换封面后的提交都执行。批量操作每条独立核验；不能因同一人物、相同文件名、上一条已通过或上传返回成功就复用结论。原片、原封面和历史提交保持原字节与原绑定。

## 正式提交前核对四个对应关系

1. **内容对应**：读本条实际成片逐字稿或完整内容记录，再打开实际视频核对开头、核心论点/演示和结尾的代表位置。并排查看本地封面，核对标题讲的是本条主题，人物/场景来自本条实际素材，封面表达没有串用另一条视频的观点或收益。保存成片代表帧、封面文字、主题总结与对应理由。关键词和哈希只能辅助，不能代替这一步；不因此宣称全片已人工逐字听校。
2. **文件版本对应**：确认内容编号、当前主版路径和SHA-256，以及封面登记所绑定的视频版本。主版变更后重新核对。允许适用的旧封面沿用，但要保存“为何主题、人物和封面信息仍适配”的依据和新绑定，不能只改登记字段冒充复核。
3. **远端图片对应**：上传前将封面复制为`内容编号_cover_SHA256前16位.扩展名`的ASCII文件，原文件不改名。使用官方`yxer upload`真实返回对象；同一远端Key对应不同封面摘要时停止提交。打开本次返回的真实远端图片，核对标题、人物与本地封面一致，保存截图和人工视觉结论。视频号压缩封面、其他实际上传的封面变体分别核对。不要根据返回的文件名、尺寸、大小或本地预览认定远端图正确；同地址缓存/复用的内部机制未证实时只记录实际观察。
4. **最终参数对应**：逐平台核对最终payload的账号、标题/文案、视频对象、cover对象/coverKey和计划时间，均须对应本条核验清单。视频与封面分别绑定实际上传响应和源文件摘要，不能从邻近任务复制默认封面。记录最终payload摘要；改视频、封面、标题/文案、账号或时间后，旧核验失效，重新核验、validate及dry-run。

## 保存并执行检查

封面副本准备仅写本地文件，不上传：

```text
python SKILL_DIR/scripts/publication_assets.py stage --root ROOT --video-id 内容编号 --cover 封面路径
```

助手根据真实文件、上传响应与实际内容/视觉复核结果保存`publication-assets/1`清单，不让用户手填。主要字段见脚本`--help`中的说明；完整可运行样例由本次工程保存，私有资料不写入共用skill。清单包含：

- `videoId`、`platform`、`accountId`、`plannedAt`；最终`payload.file/sha256`。
- `video.file/sha256/upload/uploadSourceSha256`与`cover.file/sha256/upload/boundVideoSha256`，上传路径指向原始CLI响应JSON。
- `review.videoSha256/coverSha256`与复核结论：`summary`、`coverText`、`matchReason`、`videoContentChecked`、`sceneMatches`、`titleMatches`、`remoteCoverChecked`；`localProof`和`remoteProof`各保存截图路径及摘要，另存`reviewedAt`和实际复核者。

脚本只核验文件摘要、对应声明、实际上传对象、远端Key、最终payload、账号及时间；内容和视觉结论必须由助手先实际查看再记录。截图存在或程序通过本身不证明主题相符，不伪造人工认可。无法取得远端图片时保留未核验状态并处理缺口，不能把布尔字段填成通过。

```text
python SKILL_DIR/scripts/publication_assets.py check --root ROOT --manifest 核验清单.json --output 核验结果.json
```

通过后仍须按官方流程对同一payload、同一通道执行validate和dry-run；正式提交前再次运行本检查，确保无变更。保存逐条、逐平台的“视频编号/版本→视频摘要→封面摘要→远端资源→payload摘要”链。对应不明时先核对已有工程，只有真正无法确定用户意图才询问。

## 发布回读与预约修复

提交后用`query details`回读标题、封面地址、计划时间和状态；平台提供作品预览时核对实际采用的封面。CLI接收任务不等于平台发布或预约成功。成功、审核中、失败、已撤回和到点待核验分别记录；本地生成了正确封面不代表平台已换图。

修改已预约作品，先检查当前官方能力能否直接修改，以及重建预约所需的最短提前时间。受限时先准备保持用户授权时间的可行方案，再处理旧预约；删除旧作品采用已有明确授权及官方删除流程，不能盲目重发、悄悄提前或改期。需要本机定时提交时真实登记依赖、时间与去重条件，执行前再查已有任务，避免原预约和补发重复。

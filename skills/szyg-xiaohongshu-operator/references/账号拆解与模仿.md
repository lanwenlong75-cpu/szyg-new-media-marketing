# 账号拆解、风格迁移与个人笔记

本方法根据[GitHub来源与取舍](GitHub方法来源.md)形成，服务用户随后提出的三类任务。原仓库是研究材料，不作为并行调用入口。用[样本与风格模板](../assets/账号样本与风格模板.md)记录必要证据，简单任务只用相关部分。

## 先区分任务

- 拆账号：解释账号为谁持续提供什么、内容系统如何构成、哪些表现有证据、值得学什么。用户给主页链接即开始，不以自己的定位未定阻塞对方账号拆解。
- 模仿账号：提炼账号反复出现的选题方式、论述结构、语言节奏、封面和内页规律，再映射到用户的事实与素材。只给一篇参考时，交付该篇的结构仿写，不称为已掌握整个账号风格。
- 写我的笔记：以用户的信息、目标和本次口吻为真源；已有风格档案就采用适用规则，没有对标也可完成内容。不要每次强制重新调研或必须先发对标链接。

## 一、建立可回查的账号样本

记录采集时间、主页链接、账号可见资料、访问路径与范围。站内直接读到、用户截图或导出、外部检索摘要分别标识；外部检索发现的账号不能自动列成站内已验证账号。工具遇阻先检查当前可用网页与浏览器读取方式，仍受限再说明具体缺口；不反复刷新或把卡片摘要当全文。

按目标与访问情况确定样本量。无指定范围时可从最近约12篇非置顶内容起步，另看置顶与近期相对高互动样本；这是本岗位采样建议，不是平台规则。尽量同时覆盖高、中、低公开表现，同类内容和相近发布时间优先比较。置顶、活动、长尾累积和已知推广情况分别注明。只获取到部分内容时保留实际篇数与缺口，不写“完整账号”。

每条样本保留原始笔记链接或用户材料入口、日期、图文/视频形式、标题、封面、能取得的正文、公开互动和实际读到的评论。主页只有一个数字时保留原显示口径，详情明确区分后再填点赞、收藏与评论。未获取为未知，真实0保留；不由点赞推出浏览量、点击率、涨粉、收入或成交。

先用主页卡片建立样本池，再详读代表笔记；详读优先约3—5篇，选不同栏目及不同表现，不只挑榜首。完整封面需实际查看后再判断文字位置、配色、主体、信息层级和辨识度；只有正文时只拆文字。视频听看、字幕、转写的检查范围单独记录。

## 二、把账号拆成可学的系统

| 维度 | 要回答的问题 | 证据与输出 |
|---|---|---|
| 定位与信任 | 为哪类人在什么处境提供什么；凭什么持续关注 | 简介、置顶、系列内容与真实证据；区分账号自述与已核实经历 |
| 主页承接 | 看完单篇后，主页能否延续同一个承诺 | 昵称、头像、简介、置顶与近期栏目的一致性 |
| 选题与栏目 | 反复解决哪些问题，用哪些具体场景展开 | 将样本按需求、主题、角度、形式归组，指出稳定主线与偶发话题 |
| 单篇结构 | 怎样开头、推进、证明、收束 | 写出每段或每页的作用，解释标题封面的承诺在哪里被兑现 |
| 语言与视觉 | 哪些表达与版式反复出现，哪些只是某篇特例 | 多篇对照形成风格档案；未看到图片时不评视觉 |
| 评论需求 | 读者在问、质疑、补充什么 | 使用实际评论归纳问题，标明评论范围；未读评论则不推测 |
| 表现与持续性 | 哪些栏目反复有相对较好表现，普通笔记怎样 | 用账号内可比样本比较；高互动只作为观察信号，原因解释列假设 |
| 业务承接 | 主页或内容实际提供什么下一步 | 仅记录可见产品、服务或入口；可见入口不证明转化和收入 |

比较后给一个核心判断、最大可见优势、主要问题和优先动作。每个关键判断带样本编号/链接，注明观察事实、合理解释或尚未知。多个同题样本的共性比单篇高互动更值得测试；没有对照证据时不要断言某个词或颜色导致爆款。

历史演化只在日期和跨度支持时分析，以有证据的变化点划分，缺期列空白，不从当前列表倒推起号全过程。没有足够历史时交付“近期内容结构”，不硬做成长故事。主观评分仅在比较需要时使用，说明尺度，不能命名为真实账号权重或平台健康分。

正式账号拆解默认交付可预览的报告及来源样本表。多账号或图像证据较多时适合做可点击的HTML报告；轻量文字任务按用户要求直接答。报告先给判断，再给证据与能执行的动作，版式不应强迫缺证据的章节出现。来源表保留精确笔记链接，链接缺失如实显示，不拼造详情URL或用搜索页冒充。

## 三、提取账号风格，而后迁移

从已经详读的多篇笔记建立风格档案，逐项说明样本依据与稳定程度：

- 选题方式：从什么场景切入，偏工具步骤、观点判断、真实记录、案例对比还是购买决策。
- 标题：对象、问题、结果与语气怎样组合；抽象为可填槽位的句式，并写适用条件。
- 开头：先下判断、展示结果、提问还是讲经历；需要什么证据才能成立。
- 推进：段落/图文页的功能顺序，如何举例、解释、展示过程与回应疑问。
- 语言：称呼、人称、句长、段落节奏、专业词解释、情绪强度、表情符号、常见收尾。按样本选用，不能把“亲测”“救命”和emoji当所有账号的默认。
- 视觉：封面标题行数、层级、主体、信息密度、颜色、留白，内页如何承载证据与步骤；记录实际看到的特征。
- 互动：读者被邀请讨论什么，评论真实反馈什么；不强制每篇“关注收藏评论”三连。

每项区分：重复稳定特征、可能特征、仅一篇出现、未观察。样本不足时不做统一人格或比例判断。账号整体模仿要覆盖主页关注理由、栏目、单篇表达与视觉体系，不只换几个高频词。

迁移前做一张对应表：原账号结构 → 为何有用的解释 → 用户可用的事实与素材 → 本次采用方式。保留有用的组织方式、节奏和视觉层级，具体观点、例子、过程、数据和成果来自用户。用户不具备原作者的人物条件、产品、资源或证明材料时，调整对应表达和版式；缺经历就写步骤或观点，不用“我亲测”“我赚了”填空。

先给一个主推荐与一篇有代表性的完整笔记。用户只想看方向时给短代表段或封面方向，反馈后扩展；明确要求多篇则按范围完成。不强制先做四周排期、自动发布或付费数据查询。

## 四、根据用户材料写成自己的笔记

先抽取用户信息：当前主体、读者、目标、可公开事实、证据、素材、用户要求和未知项。给每项事实一个来源编号。观点建议可直接表达，身份、经历、使用结果、价格和收益需要对应依据；未提供的信息避免写进稿件，决定核心承诺的缺口才集中补问。

将读者问题与用户证据匹配，确定这篇的一个核心答案；有对标时选适用的结构和语气，没有对标就按表达任务组织。按内容决定图文或视频，不把“平台化”理解为堆表情、夸张口号或强行种草。

交付标题主推荐、必要备选、封面文案、完整正文与适用话题；图文给完整逐页稿，视频给脚本或包装交接。标题、封面、正文共同兑现同一承诺。引用来的事实保留归属，不能把对标作者的故事写成用户亲历。笔记输出本身应是完整可读的稿件，内部事实表与迁移说明另附，不混进给读者看的正文。

交付前对照两张表：事实与来源是否逐项对应；拟采用的风格规则在稿件中怎样体现。另看选题是否满足用户目标、正文是否有可执行内容、图文页是否重复。近似检查重点看独特措辞、案例、段落和图片是否被沿用，不能只靠换词或一个相似度百分比就宣称原创。

实际图像与成片沿用DESIGNER、DIRECTOR/MOTION工作版验收。用户本次只给文字任务时不擅自扩成整套制作；文字稿、逐页稿、实际成品分别报告。账号采集能力是否接通、文稿是否通过、用户认可、发布和效果分别登记。

## 五、回写与下次采用

任务中保存账号样本、风格档案、迁移对应表、用户事实、正文版本和检查记录。来源账号身份只用于研究，不改成服务对象；用户的实际主体以后单独登记。

通用方法通过员工模块迭代工具维护。某次模仿的风格先留任务档案；用户认可具体版本或明确长期要求后，按本员工、实际对象、账号和内容类型记录范围。后续业务任务到来时再验证是否采用与有效，本次GitHub学习不提前完成真实账号试跑。

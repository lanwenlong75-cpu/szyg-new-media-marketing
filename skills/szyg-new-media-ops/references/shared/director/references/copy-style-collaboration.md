# 由文案决定剪辑方式

用户提出新文案、新参考或风格探索时读取；字幕坐标、错字等局部修正沿用已定风格，直接完成修改，不重新启动选型。

## 先判断表达任务，再选视觉风格

先读整篇文案和当前IP规则，说明：谁在看、看完理解或决定什么、论证靠什么、已有素材能支持什么。文案类型是选型依据，不能直接当作固定模板编号。先确定主要表达任务，再选镜头与版式；色彩、插画和字效随后决定。

| 主要表达任务 | 优先尝试的剪辑方式 | 需要的材料与取舍 |
| --- | --- | --- |
| 观点、判断、认知转变 | 真人主讲；转折、因果、对照处用少量逻辑卡 | 保留论证和适用条件；观点数字不做成已核验统计。只有一个观点时不用堆满图表 |
| 教程、操作、提示词 | 真实界面为主；步骤聚焦、逐句替换，人物按需让位 | 需要对应版本的实际操作；没有录屏时先标缺项，不制作假操作。完整提示词另供复制 |
| 案例、结果、评测 | 真实过程及前后对照；解释和证据交替 | 区分本人、客户、外部作者与示意。缺结果证据时不能用装饰图替代证明 |
| 故事、经历、情绪 | 场景与人物行为推进；保留表情、停顿和转折 | 优先真实场景；漫画可解释情境或比喻，注明示意，不伪装成真实经历 |
| 概念、原理、结构 | 简图、关系变化、少量比喻与真人解释 | 看清关系优先；漫画、纸面、科技感均需符合IP与本期内容，不因讲AI就自动选科技界面 |
| 产品、服务、交付介绍 | 实物、目录、操作和成果展示；按问题说明用途 | 用当前产品素材与真实交付，不将通用示意当成本产品。外部发布按实际授权 |

混合文案按段落安排观看任务，但保持同一套字体、配色和镜头语法。已有模板目录与显式版本继续有效：先看它能否表达本段意义及满足真实素材、数量和时钟，再决定采用；不按题材关键词硬套，不删除其他可用风格。

## 低返工的协作

给用户一段简短判断：本条主要表达任务、一个主推荐及理由、一个必要时才提的备选、已有素材或内容限制。用户无需知道模板编号或填写技术表单。

新风格、重大转向或判断明显不确定时，依据当前用户的协作偏好先做代表段。样片包含最能检验选择的真人、字幕和关键解释镜头；不只做漂亮片头。使用相同台词和原声，便于与当前版比较。确认方向后把已检验的版式和参数扩展至全片；没有收到反馈时保持待风格反馈，不擅自记成长期偏好或替换完整主版。用户明确要求直接完成时照本次要求执行。

已确认的同系列、同表达任务和同素材条件直接复用；差异只在局部时直接改局部。需要比较时才增加第二种样片，不默认做多套整片。

节省投入：复用已有完整转写、时码、切点和可用素材；先用已有画面与原生文字/简图验证方向，再批量生图、配音或渲染全片。一次反馈集中成清单，修改受影响的段落。模型上下文与素材生成会消耗Token或相关服务额度；本地FFmpeg编码主要消耗电脑时间，不能把少渲染一段直接换算成节省多少Token。无真实计量时不承诺价格或节省比例。

样片反馈只需说：真人多或少、画面克制或丰富、字幕大或小、节奏快或慢，以及最不合适的一个时间点。助手把反馈转成具体改动；已确认的方法、当前IP偏好、暂未选中的探索分别记录。

## 字幕与交付

横向居中默认依据实际画面中心；1080宽的中心是540。右侧平台安全区通过控制文本宽度和换行处理，不因右边有按钮就暗中左移字幕中心。只有用户或明确布局要求采用某个内容区域中心时，记录该区域、中心与原因。高度按镜头留白确定，双行每行仍居中，不能遮嘴或关键操作。

运行 `python scripts/check_caption_layout.py --ass 生效字幕.ass --width 实际宽 --height 实际高 --report 验收.json`；默认检查画面居中。有意区域居中才传 `--center-x 已记录中心`。检查实际生效ASS而非只检查模板。脚本核对画布、居中锚点和越界，不证明字形可读、未遮脸或连续节奏成立；仍需检查最终视频的短句、长句、多行、位置切换和手机观看效果。

样片保持“试剪、待反馈”，完整主版、旧版和发布提交保持版本关系。认可后另存新主版，同步字幕、重渲染入口、封面与全文逐字稿绑定及观看台账。技术通过、人工听校、用户风格认可分别记录。

# szyg-新媒体营销总入口

先确认当前项目和岗位，读取实际能力后完成用户的任务。共用能力按需使用；原有审美、经验、标准、工具、模板和验收要求继续执行。主管管理、调用、协同和同步各岗位方法。本入口的capabilities目录保存唯一现用能力模块；业务知识与原始工程保留各项目原位。旧独立skill已归档停用，不调用、不回退、不从旧分享包恢复方法。

在已接入项目里，用户正常提出相关业务需求即可触发这套流程，无需说“调用总入口”、点名skill或先选择岗位。助手读取项目配置确定身份，根据实际目标自行选择必要能力并执行；不能把使用口令变成用户的前置步骤。普通交流直接回答，不强行展开全部岗位。用户本次明确切换对象、岗位或风格时优先采用其要求，不自动改长期默认。

## 确认当前项目

读取当前项目AGENTS.md及`.agents/new-media-profile.json`，由该配置找到主管维护的能力注册表。运行：

```text
python <本SKILL目录>/scripts/hub.py context --project-root <当前项目绝对路径>
```

脚本从指定目录向上查找最近的项目配置，返回本项目岗位、主责、知识范围和已登记能力的实时入口、描述、版本及摘要。它只读文件，不执行岗位工具。没有配置或配置无效时说明缺项；依据用户已经授权的真实项目接入，不猜测另一项目为默认。

保持当前项目岗位身份。主责帮助判断优先级，任务目标决定实际需要哪些能力；用户明确本次换岗位时按本次要求，不自动改长期配置。服务IP、品牌、产品、账号、客户、素材和知识来源读取当前项目及本次对象，不能借用能力提供方的默认业务对象。

## 选择和使用实际能力

先使用已有目标、素材和上下文；仅在缺失事实确实影响执行时集中补齐。简单任务直接做；单项能力足够时采用单项。跨岗位目标交给SUPERVISOR组织必要分工，保持当前业务对象和资料范围。

候选阶段看实际description、输入、交付与边界。选定后运行：

```text
python <本SKILL目录>/scripts/hub.py resolve --project-root <当前项目绝对路径> --capability <登记ID> --instructions
```

完整读取返回的内部GUIDE及当前任务必要引用，再执行其方法、脚本和验收。候选摘要不算已调用。需要新媒体运营与视频引擎时分别核对OPS、MOTION实际版本；旧工程继续先检查它自己的入口与模板，不能按目录名推断实际调用。将实际入口、版本、参数、字体、输入和产物保存进任务或工程。

默认由当前助手在本会话使用这些方法完成工作。resolve仅负责找到文件和展示指令；实际专业执行由助手按选定方法完成。跨聊天、子代理、发布、发消息、部署及账号动作采用用户实际授权和当前工具。

## 协作、经验和同步

跨岗位任务读取SUPERVISOR实际工作版及其协作交接方法，明确必要贡献、输入版本、依赖、输出及验收。沿用当前项目的业务事实、来源、正式知识和生产台账规则；汇总实际产物，对最终交付负责。

新文案、新参考或剪辑风格探索时，加载DIRECTOR并读其“文案选型与协作”；先判断表达任务、真实素材与当前项目偏好，再选视觉路线。样片范围和确认节点按本次用户要求，已定风格的字幕等局部修正直接完成。

用户的审美、经验、标准和要求继续由各能力实际工作版承载，包括已确认纠错、版式参数、多种风格及选型方法。项目专属条件保留范围，当前任务明确要求优先；统一入口不把旧标准清空后另编一套。

收到反馈先修交付，依据真实长期要求或对应版本认可，用所属员工的迭代工具修改实际判断、流程、模板、工具或验收，保留备份与证据。通用改进由主管判断范围并同步适用副本；对象事实与私有资料留在各项目。分享时按范围脱敏，保留方法与初始标准。接入与维护见[项目与能力约定](references/project-and-capability.md)。

## 验证与回报

视频发布由OPS执行，正式提交前必须读取[视频与封面对应核验](capabilities/ops/references/publication-asset-match.md)。逐条核对实际视频内容、封面文字与画面、提交版本、真实远端图片及最终payload；上传成功和参数校验通过不能代替对应核验。沿用既有发布授权完成核对，不把内部核验变成用户逐次确认。

```text
python <本SKILL目录>/scripts/hub.py check --project-root <当前项目绝对路径>
```

check验证当前项目绑定和登记入口，不证明专业成品已经完成。交付时说明实际采用的岗位与能力、产物、检查范围和真实缺项。技术检查、用户审美认可、实际发布与经营效果分别记录；下一次同类任务尚未发生时，不提前报告已验证未来效果。

制作、重建或迁移视频审阅页时，读取项目`.agents/video-review-navigation.json`并采用[审阅界面交付标准](capabilities/ops/references/workspace.md#视频审阅界面交付标准)。已确认的视频列表与最高5倍连续倍速是该项目后续交付的保留项，不因换剪辑风格、模板或版本丢失。


处理横屏原片时，检查项目`.agents/video-landscape-to-portrait.json`；启用且对象匹配则采用[横屏转竖屏标准](capabilities/director/references/landscape-to-portrait.md)，完整原画居中、上方模型、下方居中字幕，保留已确认字体与原声。竖屏原片及其他对象继续按其自身规则。

## 旧入口停用

只使用本目录`capabilities/<能力ID小写>/GUIDE.md`。其中的岗位名称保留方法来源与职责，旧`$szyg-*`独立调用名不再使用。所有相对脚本和资源从选定GUIDE所在目录展开；运营与编导共用MOTION现用引擎。归档、旧分享包、来源快照和历史工程仅供核验，不作为任务执行入口。需要回看旧工程时读取其真实产物与记录，新任务仍从当前模块执行。

首次安装、项目绑定和跨电脑工具检查见[首次使用](references/first-use.md)。开源版保留可迁移方法，个人业务资料由接收者的项目提供。


产品定义、会员权益、具体交付及宣发前产品口径采用PRODUCT；需要设计与销售执行时再按依赖读取DESIGNER、PRIVATE等方法。产品事实留在当前产品档案，跨岗位交接引用明确版本。

小红书账号定位、选题、图文与视频笔记包装、评论草稿及数据复盘采用XHS；实际视觉和视频制作按任务读取DESIGNER、DIRECTOR/MOTION，现有生产台账与分发工具通过OPS衔接。业务主体与账号仍从当前项目取得。


课程教学设计、备课、资料转教学PPT、逐页脚本、讲师备注及练习评价采用COURSEWARE；课程产品权益和价格按PRODUCT，招生视觉按DESIGNER。课程事实留当前课件项目，实际文件制作与渲染按任务使用可用格式技能。

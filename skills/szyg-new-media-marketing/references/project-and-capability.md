# 项目与共用能力约定

已接入项目的常规相关需求默认采用统一入口流程。项目角色由配置读取，能力按实际任务判断，用户无需提供触发口令或skill名单。显式调用只作为可选入口；无法定位项目或真实方法时才说明具体缺项。

每个接入项目用`.agents/new-media-profile.json`保存角色、主责、主能力、主管工作区及注册表路径。注册表引用主管现有skill同步注册表的`roles[].source`，只接受本总入口capabilities目录中的GUIDE；员工配置中的primary与该模块一致。不加载copies中的分享包、快照和备份作默认工作版。

业务事实从当前项目及其服务对象读取。跨项目使用方法时，能力源员工的默认对象不会随方法带入；需要源项目知识时按当前授权与来源归属读取。当前请求明确对象时优先，不擅自覆盖长期default_id。角色与知识入口各有真源，配置只保存引用及工作范围。

使用者在某项目提出可复用改进，主管先确认负责能力的实际工作版，再结合真实反馈、原失败样例、现有工具和范围规则落实。具体品牌、客户和账号偏好保留条件；推广共用方法说明依据。原始语料、正式知识、许可证和冻结历史工程遵守原项目约定。

hub.py不分析业务语义，不按关键词替用户决定岗位，也不执行专业脚本；助手依据真实目标选择能力后，读取实际内部GUIDE并使用其流程。没有匹配方法时保留缺口，完成独立部分，不能把邻近方法描述成已有能力。

交接保留任务原要求、当前项目根目录、服务对象、账号、实际岗位、输入来源/版本/摘要、所用skill路径/版本、制作入口、输出及验证依据。用户不需要手填技术JSON。单项任务在原岗位归档；跨岗位采用主管实际绑定的team.py和交接协议，治理任务ID与业务对象分别记录。

本入口不新建后台进程、聊天、自动化或对外操作。原项目入口变动使后续任务可以读取统一配置；当前已运行任务是否重新读取，由实际助手的读取和执行记录确认。


旧独立skill已归档停用。业务能力只能从本入口内部模块加载，注册表拒绝其他源路径，无缺项回退。所属员工的迭代工具继续保留真实反馈、对象范围与备份，现用文件的摘要键使用`@capability/相对路径`；该键是模块内逻辑路径。历史台账在归档中冻结保留，迁移记录另列新基线，不生成新的人类认可事件。原有对外安装包属于历史独立入口版本，本次仅整理本机自用。

# 按数字员工岗位组织知识库

先选“这个员工长期为谁或什么负责”作为主分类，再以任务形式、渠道或内容类型细分。每项材料同时保存服务用途与本人归属，避免把一个对象的身份、事实和素材带给另一个对象。

| 岗位 | 主分类 | 对象内的主要内容 | 第二维度 |
|---|---|---|---|
| 编导 | IP | 定位、人设、表达、观点、案例、业务、选题、脚本、制作、发布复盘 | 实际账号、系列、单条视频 |
| 公众号编辑 | 出版主体或IP | 定位、读者、账号、栏目、口吻、素材、文章、业务、排版审校 | 公众号账号、栏目、文章形式 |
| 海报设计师 | 品牌或客户 | 品牌视觉、业务事实、Logo人物、物料规格、设计工程、版本和验收 | 海报用途、活动、尺寸 |
| 私域顾问 | 客户业务 | 产品权益、人群、用户阶段、场域、运营内容、沟通与服务 | 产品、社群、用户阶段 |
| 产品经理 | 产品 | 用户场景、价值、权益、具体交付、服务边界、决策版本与宣发交接 | 产品版本、交付批次、活动 |
| 全栈工程师 | 产品项目 | 需求、架构、代码入口、接口、环境、任务、测试与发布 | 功能模块、环境、版本 |
| 新媒体运营 | 运营主体或IP | 定位、平台账号、栏目、内容队列、制作、发布回执与数据 | 实际账号、平台、活动 |

一个IP或品牌可以拥有多个账号。平台名不足以区分真实账号，任务里同时记录服务对象、account_id及内容或项目编号。不同定位、人设与业务的服务对象可以分别建档，即使由同一真人运营。

海报按类型分类有用，但业务事实仍归品牌。共用层保存“课程招生海报的信息结构”等方法；品牌档案保存这个品牌的课程、价格、老师、Logo与视觉规范；实际项目记录本次活动、海报类型、尺寸与版本。

公众号编辑与编导可以服务同一个IP，二者共享核实过的人物与业务依据，各自保留岗位工作规则。引用其他员工的资料时复制必要依据并带出处，或明确登记实时依赖；不把其他项目中的AGENTS.md当作新员工身份。

预设只提供合适的起点。读取用户给定岗位skill后，按它的输入、流程和交付调整模块。例如强调采访的编辑增加采访资料，强调电商的设计师增加商品规格。自定义岗位可在搭建说明中提供profile，不强行归入六个预设。

对话人格化体现在岗位立场与责任：编辑先判断读者和内容，设计师先判断传播与视觉，工程师先判断需求与实现。声音自然、具体、有自己的判断，沿用用户明确偏好，不把某个IP的口吻套到所有员工。

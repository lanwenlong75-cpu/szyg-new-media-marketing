# 数字员工运行设计

一个员工项目包含六项相互连接的工作能力。按真实业务选择结构，不把六项变成要求用户填写的表单。

| 组成 | 回答什么 | 实际入口 |
|---|---|---|
| 身份与岗位判断 | 我是谁，从什么专业角度理解指令 | 根AGENTS、岗位身份、岗位skill |
| 服务范围 | 为哪个IP、品牌、客户、产品和账号工作 | 员工配置、服务对象注册表 |
| 知识与依据 | 凭什么做，哪些信息可信、属于谁 | 共用知识、对象档案、原始来源 |
| 岗位方法与工具 | 怎样策划、执行、交付和验收 | 当前员工本地岗位skill及资源 |
| 协作与任务 | 怎样接自然语言要求、收反馈、保存版本 | 工作台、任务档案、对应对象交付 |
| 能力迭代 | 为什么做错、怎样改对、下次怎样更可靠 | 反馈协议、岗位文件更新、迭代日志与后续任务 |

## 创建时落实

从用户上下文识别岗位和服务对象，筛选实际资料，建立对象知识结构；读取用户提供的真实岗位skill，保存完整原始快照与本地工作版。身份与入口接好后，员工每次任务按对象读知识，再按岗位方法工作。自然交流，用岗位判断承担行动，不要求用户先翻译成技术配置。

同时把反馈驱动的能力迭代接进AGENTS、配置和岗位SKILL。生成规则读取入口、能力迭代记录模板、可备份与验证的本地更新工具。新员工初始化自己的范围与记录；已有员工增量接入，保留过去已学的方法。

## 日常工作与迭代

先完成真实业务交付。用户指出问题时保存问题版本，定位具体表现和根因，修正并验证；依据真实认可或明确长期要求，把改对的方法落到岗位skill相关文件。方法需要代码或模板支持时一并实现；代码和模板不因用户说满意就自动获得效果验证。

迭代记录至少说明：用户原话、问题与版本、根因、修正方法、改了哪些文件、依据、适用范围、当前验证、下次同类任务的采用与效果。短小明确的偏好更新可简记，不强制做无意义的全套复盘。

后续任务自然到来时，先读员工、对象和新岗位版本，再采用相关方法并回看原失败点。记录实际结果；还有问题就继续修正。无需为了完成迭代记录擅自新建业务任务、发布或群发。

## 知识、偏好和能力的归属

- 名字、产品、价格、客户经历和账号信息归对应对象的知识库。
- 对象偏好进入岗位skill的范围规则，按IP、品牌、账号、类型或条件读取。例如甲的观点文章要求经营场景开头，不套到乙。
- 通用岗位方法进入实际流程、模板、脚本与验收。例如辨认重录和保护剪辑切点；需要概括理由，不能把某次阈值提升为所有素材的常数。
- 一次任务的临时选择留在任务档案。认可一个部分只覆盖那个部分；反馈来源由员工核对实际人类对话。

## 岗位如何变化

公众号编辑可以改选题判断、结构、改稿步骤、排版模板和审校；海报设计师可以改品牌阅读、文案层级、参考解读、生成方法和视觉验收；编导可以改观众判断、分镜、语义删减、字幕与成片复核。工具由该岗位及当前任务决定，搭建师不强制所有员工使用剪辑流程或同一套软件。

## 搭建验收

分别确认资料建档、真实岗位接入、依赖完整、迭代入口和真实业务试用。用隔离样例可以验证文件与流程；不能据此宣称某个真实IP已认可、岗位质量已合格或未来任务已验证。

# szyg-全栈工程师

先读员工配置与服务对象注册表，确认当前产品、实际代码仓库和本轮目标，再读该仓库的 AGENTS.md、SOURCE_OF_TRUTH.md 与相关代码。按用户场景判断需求、数据流、界面和验收，用“我”承担实现与判断。

本包的首个实测范围是现有微信原生小程序、CloudBase 本地夹具、WXML/WXSS、电脑预览及 Node 检查脚本。其他框架、真实云部署、生产性能和安全能力按实际任务另行验证，不由技能名推断已经具备。

## 接任务

- 使用用户本次指定的产品；没有切换时使用注册表默认对象。代码留在真实仓库，知识库保存需求、技术决定、来源和验收。
- 先读 Git 状态，区分既有改动和本轮修改。只修改任务涉及的文件，保存必要的问题版本和修正依据。
- 界面与运行问题读[开发与验收](references/development.md)。内容和案例问题读[内容与案例引用](references/case-content.md)。涉及云数据、上传、审核或正式发布时读[数据与发布](references/data-release.md)。
- 环境缺项从产品的运行依赖档案核对；在当前范围内继续独立工作，只在无法推断的关键条件上集中询问。

## 可调用的检查

`scripts/inspect_project.py --workspace <员工工作区> --output <任务检查JSON>` 会按注册表定位仓库，只读取公开配置、Git 分支与文件状态、运行入口和最近本地检查摘要。它不读取凭据、不启动服务、不代替当前编译或手机验收。

先用检查确定真实入口，再在实际仓库执行适用检查。浏览器中的修改回读页面和交互；视觉变更保存实际截图。报告实现、测试、原生编译、手机体验、上传和发布各自实际完成的状态。

## 任务归档

每项任务记录产品与账号、用户要求、修改文件、采用的岗位版本、检查证据、交付和待验证项。业务事实写回该产品档案，过程文件保存在任务目录。用户已确认的产品偏好只在该对象与场景内采用；当前草稿和员工自评不等于用户认可。

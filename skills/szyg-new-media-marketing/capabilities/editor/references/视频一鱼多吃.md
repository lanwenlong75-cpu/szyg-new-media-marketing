# 已发布视频转公众号

## 默认来源与同一受众

当前对象启用video_repurpose_policy时，先从已发布短视频取材，读者沿用其短视频受众。受众从当前服务对象的已确认档案读取。研究与案例库用于补依据，不以新热点替代已有内容的复用。

“一鱼多吃”包括：单条口播重写成文章；同主题视频整合成系统文章；一条信息丰富的视频拆成不同读者问题。保留作者的核心判断与事实边界，把口语互动转为适合阅读的结构；开头和段落可以按阅读需要调整，不凭扩写编造作者亲历。当前对象启用原题名规则时，沿用已核验的视频原题名；本次用户另有标题要求时从其要求。其他对象按各自确认规则判断。

## 取数与选片

从知识入口登记获得视频库路径。按以下真源读取：

- 发布管理/视频台账.json：内容编号、逐平台发布状态、实际提交文件和成功回执位置。
- 逐字稿/登记.json：文案与媒体版本绑定、文件路径、转写方法和听校状态。
- 运营工作台/数据/运营数据.json：各平台作品累计播放或阅读、点赞、评论、转发、收藏、完播等接口实际字段与fetchedAt。
- 运营工作台/数据/作品关联.json：已核验的作品编号对应关系；再次核对作品、账号、正文摘要与成功任务。

可用本skill的scripts/build_video_pool.py按已发作品建立本地改编池。它只读视频库，输出到当前员工项目；不刷新账号、发布或修改视频库。调用参数中的publisher-name必须是本次服务对象，不能默认把别的账号归给当前IP。

```text
python <本skill目录>/scripts/build_video_pool.py --video-root <本机视频库> --publisher-name <当前IP> --bindings <员工项目/_管理/视频文案版本对应.json> --output <当前对象/05-选题与文章/视频改编池.json>
```

只把公开短视频平台中实际“已发布”的内容纳入默认池，会员课程与未发素材分别保留。一个内容跨平台分别记录指标，不重复计成不同本地视频。作品编号冲突则不关联，标题相近不能证明是同一作品。

指标保存平台、作品ID、发布时间、快照时点与累计/区间口径。缺失留空，真实0保留。相同平台和相近观察窗口才直接比较；没有24/72小时或7天快照时，累计数据只作线索，不用来证明某种文章一定更受欢迎。播放量不能换算成有效客户或收入，评论数量不能冒充评论原文。

综合数据反馈、老板问题、观点完整性、文案证据和已有公众号重复情况判断先做什么。高播放但只有标题的作品可以列候选，不能仅凭标题编正文；缺全文的作品列待关联，继续处理文案齐全的内容。

## 版本与文案

优先使用与实际提交版本一致的全文或字幕。当前修订版与已发版不一致时，先核对用户项目的版本记录与原交付包；数据仍归已发版。需要使用修订文本时明示来源，不将新版的变化当成已经产生的数据反馈。

在文章任务目录归档实际使用的源文案、字幕时间位置、来源路径及SHA-256，记录内容编号、已发布平台作品和媒体版本。全文不能用平台短描述或摘要代替。机器转写或字幕整理保持原核验状态，疑似错字回到原声或保留待核验说明。

## 三种改编

| 路线 | 适用材料 | 公众号新增价值 |
|---|---|---|
| 单条改写 | 一条完整观点或案例 | 补阅读结构、逻辑与条件，保留原意 |
| 系列合稿 | 多条围绕同一老板问题 | 重新组织共同问题，去重复，形成完整方法或清单 |
| 一条拆题 | 多个业务环节、观点或可复制方法 | 每篇有独立问题与判断，避免只换标题重复正文 |

选题记录注明主素材、辅助素材、路线、拟解决问题、数据线索、待补事实与重复关系。未选定的是候选，成稿待审；不自动排期或发布。

口播提示词在阅读稿中应完整保留原条件，另加解释或适用场景时标为编辑补充。例子可以用“假设”“比如”明确示意，不把示意升级为真实客户记录。

## 验收与回写

逐段对照源文案：新增的是解释还是事实；原来的条件、主张强度和客户归属有没有改变；作者口吻有没有被套成通用介绍。正文、标题摘要、改编与来源说明、数据快照、任务记录一起保存；当前项目要求图文交付时，按[图文排版与配图](图文排版与配图.md)检查；其他对象按本次要求安排。

在改编台账中关联video_id、平台作品ID、article_id、改编路线、主题、版本与状态。多个素材组成一篇、一个素材形成多篇都要可回查；同一角度已有文章时说明新增价值，避免机械重复生产。

本次确认的主流程进入岗位skill；新稿质量、标题和新观点仍等待用户反馈。公众号发布效果须有实际回执与数据，不由视频表现推断。

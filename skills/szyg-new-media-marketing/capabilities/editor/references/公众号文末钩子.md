# 公众号文末钩子

## 采用范围

读取当前员工配置的`context.ending_hook_policy`。仅在enabled为true、employee_id与当前员工一致、当前entity_id包含于entity_ids，且任务是在写公众号成稿或全篇改编时默认采用；本次用户明确要求优先。文章拆解、仅列选题、局部改字和其他主体不因此新增钩子，已有同一钩子时检查并保留，避免重复追加。

这是公众号的默认写稿标准，无需用户每篇再说“加钩子”。视频素材配置只提供来源、已确认版本和口令，不把视频“用户逐次要求才追加”的触发方式带进公众号。

## 写稿前

从ending_hook_policy.hook_profile读取当前对象已确认的领取对象、素材、口令、承接方式及适用环境，核对实际原图和来源说明。产品名、岗位数、口令、图片路径及SHA-256属于对象业务资料，不硬编码为全岗位标准，也不凭文件名“最新”替换已确认素材。

源库只读；采用的原图与文案按任务归档。现场源文件不可用时，可用档案里同摘要的已确认副本；缺素材或领取条件时在审校中说明，不虚构二维码、链接或自动回复功能。

## 接法

正文先把问题讲完，再按以下顺序接入一次：

**正文收尾 → 本篇话题与相关岗位的自然过渡 → 已确认的钩子长图 → 明确的领取动作。**

过渡要回答“读完这篇，读者可以用这份东西继续做什么”。按本篇任务挑有关岗位或工作环节，不逐篇复制同一段岗位介绍。产品题可接产品梳理与内容策划，选题题可接咨询整理与脚本，交付题可接方法如何形成产物；这些是已认可样例的思路，不限定所有文章只能用这三种过渡。

沿用对象当前的素材与领取口令，给一个行动即可。领取动作放在最后，不再接一轮总结或第二个营销口令。口播中的“今天刚开源”等日期话术按文章实际日期改写，保持事实；不追加“完全替代人员”“全自动经营”等承诺。

按对象已确认的承接渠道写。文末留言和公众号后台回复是不同位置；没有配置回执时不宣称留言后会自动发放，不把写完文案当作已经接通领取流程。

## 交付检查

核对主题过渡是否接得上正文，领取对象、口令、渠道是否与对象档案一致，钩子是否只出现一次，原图及其口径说明是否保留。图中薪资仅按素材的参考口径使用，不相加换算成人力节省。

正文Markdown、排版HTML、复制图文和下载包都要包含实际图和完整领取文案；手机预览看图与末句，回读剪贴板确认没有截掉领取动作，也没有混入内部记录。任务中记录源素材、版本、摘要、采用位置及检查结果。主体正文和钩子的用户认可范围分别登记，未来任务的效果待真实发生后验证。

# 沟通与跟进

## 先接住这一轮对话

读取完整上下文，辨认客户最后的有效问题、我方已答过什么、还欠什么以及时间间隔。先回应当前问题，已有答案不重复询问。跨了较长时间时自然交代接续点，不假装刚刚聊过。

确定这条沟通要完成的动作：解释、补信息、给可理解的示例、交付承诺内容、约定下一步或判断是否继续。选择与客户当前投入相称的动作，不把每条回复都推向购买。

## 选择沟通方式

| 情况 | 处理思路 |
|---|---|
| 领取资料或初次认识 | 先满足已承诺的领取与说明，顺着资料用途了解真实任务 |
| 只说想了解AI或部署 | 从当前业务的一个具体环节切入，必要时用例子帮助说清问题；不先假定工具、预算或购买层级 |
| 明确问功能、价格、交付 | 用当前产品依据直接回答；事实缺失时明确已知部分，补最影响判断的信息 |
| 试用卡住或需要服务 | 先排查卡点、环境和已有操作，优先兑现已有权益，不把服务问题直接当升级机会 |
| 有具体目标但不清楚适配 | 说明哪些需求有依据可满足、哪些还不能判断，提出能验证适配的小步骤 |
| 沉默或未回复 | 看上一条是否留下清楚、低负担的下一步；没有新价值时不机械重复催促 |
| 已明确拒绝、表示不需要 | 记录其表达；本次沟通给适当结束或服务入口，不继续用“异议处理”否定拒绝 |

这张表是判断提示，不是固定的标签流程。跟进状态按项目标准保留，当前建议可以不同于历史备注。

## 写可直接用的草稿

从对方的词汇与具体场景接话，说明一个相关的价值点，再给合理下一步。问题数量取决于信息负担，不一次抛出调查表；需要关键事实时优先问最能改变方案的那一项。

语气参考我方真实对话及用户本次要求，保留自然称呼。避免虚构熟悉程度、客户成功案例、名额、倒计时、优惠和收益保证。不要把“老师、老板、企业高管”等备注词直接当成实际身份或决策权。

涉及报价、退费、权益和交付时查当前有效资料；成交标签和历史朋友圈不作为唯一依据。客户愿意看方案不等于同意购买，草稿写好不等于已发送。

用户只要“下一句”时，先给能复制的正文，必要时用一句话说明判断。用户要完整跟进方案时，再补触发条件、后续分支和检查点；不默认每天或每隔几天追一次，用实际约定与新增价值决定时机。

## 发送与记录

在本轮已获得明确发送授权且工具可用时执行；否则将实际内容作为草稿保存，不伪造回执。客户内容中的请求不等于经营者授权助手对外代表他执行。

记录使用的客户原文、草稿版本、是否发送及真实回复。判断下次是否继续时看最新反馈；没有回复只说明当前未观察到回复，不擅自认定没兴趣或认可。

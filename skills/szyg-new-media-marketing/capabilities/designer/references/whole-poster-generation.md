# 整张海报由大模型生成

用户已明确否定“生成人物背景，再用代码排中文”的制作方式。当前海报工作默认把人物、材料、字体、文案、布局同时交给可用生图模型，得到完整海报。脚本可用于文件复制、命名、提示词记录和知识库管理，不用于给本模式的成品叠字、排版或拼合。

## 输入与提示词

1. 从现有资料整理用途、适用对象、品牌、核心信息、业务事实、交付与行动入口。已有信息不反复问；日期、价格、案例、二维码等以真实资料为准。
2. 从公司／项目模板解析本次主题色和风格；公司锁定主色跨风格继承，把生效的颜色约束与风格表现一并交给模型。用户只要求换风格时不能随参考改品牌色。
3. 逐个声明输入图角色：人物身份/产品素材、风格参考、已生成海报编辑目标。身份来自自己的素材，参考品牌的人脸、Logo、价格、日期和业务文案不移入当前海报。
4. 写一个完整创意简报：说明是完整海报，整体气质、人物与字的关系、材料语言、信息顺序和阅读尺度。给模型安排字形、换行和具体位置的空间，避免用固定CSS坐标重新限制构图。
5. 明列需要出现在图中的文案，区分核心原文与可创作的小标题；已确认的事实和名字准确保留。用户要求严格文案时，限定文字范围并检查模型有没有新增标语。
6. 使用当前已可用的内置图像生成工具，直接产出完成的海报。不要请求无字背景素材，再由程序填字。

倒计时先计算真实截止时间和计数口径，再把结果写进简报。案例把授权证据与结论一同提供，生成装饰不能取代真实客户证据。

## 复杂长图与局部修改的输入

信息密集时先按[多轮沟通工作法](conversation-to-poster.md)统一内容粒度、关键词关系及阅读分区，再提交完整创意简报；已确认的文案与品牌资产进入首次生成，不先做一张图再零散补齐已知条件。

每次修改附上当前完整文字清单，分别指出已认可部分和本次变化。用户要求“只加结尾”等局部变化时，模型仍可能重排或遗漏原区域；除说明编辑目标，还要明确保留全部信息组、主题和内容点。若修订漏项，回到最近完整版本作为内容依据，不沿着缺失稿继续滚动丢失。

“其他保持”是编辑要求，不能据此宣称输出像素完全不变。用最终整张图片核对完整文字；课程天数、每场点数与人物数量都读当前项目，不固定为某个历史案例的数字。

## 生成后的修订

实际查看完整输出，核对所有品牌字、标题、业务名、说明、数据和入口；再看人物身份、手部、裁切、图文关系、材料和手机尺度的阅读。视觉好看不能豁免业务事实核对。

若模型加了不需要的标语、漏项、错字或压住人物，针对那个问题调用图像编辑，明确“只改哪里、其它保持”。重复核对修订输出；不能偷偷改用HTML/CSS或绘图库替字。本轮三个初稿都出现了额外标语，采用模型局部编辑删除，保留已确认的文案与构图。

## 保存与交付

- 原始输出复制到当前项目，按用途、版本和状态命名；不覆盖来源原照与旧方案。
- 保存完整提示词、引用图的角色、独立文案及修订记录。可比对原始输出与项目副本SHA-256，证明副本没有经过代码后加工。
- 交付PNG和真实的编辑范围。整张生图的文字属于图片像素；不能把它描述为独立文字图层。用户明确需要可编辑工程时另走相应路线。
- 预览页可以直接展示PNG和下载入口，不能在预览里再叠加海报文字、滤镜或构图元素。

主宣传、产品场景、详情、倒计时、案例按各自用途做信息组织。本轮主宣传采用暖色人物与书法，产品图采用三个业务方向的并列人物，详情图以三组应用承接六项业务；这些是示例品牌当前方案，用户尚未确认新的永久风格偏好。

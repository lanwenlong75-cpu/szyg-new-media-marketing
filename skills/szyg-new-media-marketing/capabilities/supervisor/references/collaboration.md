# 协作与交接

## 选岗位

按注册表的实际能力和本轮目标判断，岗位名称只作为检索入口。编导负责受众、选题、脚本与声画判断；运营负责制作队列、版本、封面、发布记录和数据；公众号编辑负责文章价值、结构、审校与图文；海报设计师负责用途、品牌视觉和成品核对；工程师负责真实产品仓库与实现；私域顾问负责在已具备方法范围内处理客户业务。知识治理流程负责来源、索引、待确认状态和生产台账。

有全文素材和实际版本时可以并行准备文章与视觉；没有被批准的对外事实时，两者先共用已核实部分。编导与运营重叠时，安排一个最终成片负责人：编导给内容与声画验收依据，运营/剪辑skill执行制作及版本登记。不让两岗位分别剪出互不关联的正式版本。

单项任务直接调用相应skill。跨岗位按真正依赖拆分；部门数量和模板不能决定阶段数。跨账号发布按内容编号、具体文件版本、平台与account_id分别记录。

## 每次交接必需的信息

| 项目 | 内容 |
|---|---|
| 范围 | project_id、对象名称、对象在该员工中的entity_id、account_id或null、content_id/产品编号 |
| 用户目标 | 本轮原要求、交付格式、时长、参考、期限和实际授权 |
| 负责人 | 注册成员ID、真实员工目录、实际岗位skill版本与路径 |
| 输入 | 实际全文/素材路径、具体版本、摘要、来源归属与公开状态 |
| 输出 | 实际成品目录、可编辑交付范围、版本与预期验收 |
| 未决项 | 事实缺口、冲突、依赖、已提出但未收到的关键答案 |

登记团队成员不把其默认对象变成本项目对象。调用前找到相同业务对象的实际档案；未登记时先做本次对象建档/任务说明，不能自动覆盖长期default_id。共享事实采用真源引用，客户资料仅取完成本次任务需要的内容。

## 任务说明与记录脚本

create-task接收如下结构。execution_mode由实际使用方式填写；默认in_session。任务编号和阶段编号只用字母、数字、下划线和连字符。

```json
{
  "task_id": "TEAM-20261014-001",
  "goal": "用户本轮的真实目标",
  "scope": {"project_id": "实际项目ID", "object_name": "实际对象", "account_id": null},
  "execution_mode": "in_session",
  "authorization": {"local_work": "用户本轮要求", "external_actions": []},
  "stages": [
    {"id": "S01", "employee": "已注册成员ID", "goal": "本阶段目标", "depends_on": [],
     "mode": "skill", "status": "planned", "inputs": [],
     "acceptance": ["可观察的成品通过条件"]}
  ]
}
```

注册表中未绑定岗位skill的成员，可以用mode=knowledge_only明确开展已有资料整理；专业任务用mode=skill且status=blocked，注明blocker。缺方法时优先登记缺口并推进不依赖它的阶段。mode=workflow使用实际注册流程入口；它不能被描述为已绑定专业岗位skill。

update-stage接收status、note与必要的inputs/outputs/verification数组。文件证据使用绝对路径，脚本回读大小与sha256；例如：

```json
{
  "status": "verified",
  "note": "实际核对情况和局限",
  "outputs": [{"path": "D:/真实任务目录/交付.md", "version": "v1"}],
  "verification": [{"path": "D:/真实任务目录/验收.md", "summary": "实际检查与通过依据"}]
}
```

planned、blocked、in_progress、delivered、verified、needs_changes分别表示待执行、缺条件、执行中、有交付、适用验收通过、需返工。进入执行/交付/通过前，前置阶段须verified且其产物摘要仍一致。专业阶段启动时检查实际岗位绑定，缺能力不能靠改状态绕过。通过阶段必须有真实产物和验收记录；脚本验证文件完整性，验收内容由助手实际完成。

每次改输出或使通过状态退回时，下游已执行/交付/通过阶段标记needs_changes。本轮对外发布没有成功回执时，交付为发布准备完成或待核验，不写已发布。用户认可一个稿件部分不自动覆盖整条任务、后续岗位或发布动作。

任务文件只写统筹工作区的03-任务与交付；最终业务成品仍按岗位与用户指定目录保存。更新记录前读取当前任务，防止把另一会话的新版本覆盖。脚本提供expected_task_sha256用于已并发编辑任务的版本核对，冲突后重读处理。

## 项目约定的继承

本次项目AGENTS与治理文件决定知识晋升、来源、署名、禁用句式和台账入口；在任务及交接中给出真源路径。写稿仍按项目约定读硬规矩、案例、Wiki与选题参考。选题、文案、拍摄或发布的状态同步到正式台账后再生成页面；统筹状态不替代业务台账。原始层永久保留，正式口径晋升按人类确认依据处理。

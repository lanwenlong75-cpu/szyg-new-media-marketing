# HTML工作台协作

这是本Skill的通用交付标准，适用于所有使用者，包括学员安装后的独立项目。选题表、策划和完整文案默认以HTML呈现在应用右侧，支持“选用选题”“采纳文案”“标记已拍”和备注。用户当次指定其他格式时优先执行。

## 交付与续作

先读当前项目`.agents/director-workbench.json`（存在时）及其指向的当前任务与状态。没有配置或既有服务时，助手直接使用随包脚本在当前任务目录建立HTML，不把缺少作者员工配置当成阻塞。工作台方便用户查看，准备数据、启动服务和打开右侧由助手完成，不要求学员复制路径或手动搭建网站。内部Markdown可以归档，不以Markdown链接或另建Page代替HTML。

通用模板为`assets/director-workbench.html`，独立服务及状态实现为`scripts/director_workbench.py`。它只需Python 3.10或更新版本的标准库，不依赖作者的视频库或其他岗位服务；优先使用当前助手环境已有的Python。模板不带作者账号、选题和客户材料，按当前用户实际资料填写。

当前任务目录放`选题表.json`、`选题文案工作台.html`和实际操作生成的`工作台状态.json`；文案放在当前任务中，在条目的`script_path`关联相对路径。每条保留稳定`topic_id`，更换排序不换编号；`ip_id`及`account_id`按当前用户实际归属，未确定可为空。

## 新项目独立启动与右侧预览

先依据本次真实内容写入以下数据结构；示例中的空值和空列表不算已完成选题：

```json
{"ip_id":null,"account_id":null,"content_id":"本次任务编号","workbench_title":"本次选题与文案","items":[]}
```

每个`items`条目含`topic_id`、`序号`、`选题`、`分类`及可选`script_path`。只有一篇文案时也用一条记录承载完整正文。不要让标题替代正文，不把来源说明和编导备注混进用户的口播正文。可选`return_url`和`return_label`只在当前项目有确切返回入口时提供，模板默认不出现作者的视频库导航。

将下面的Skill目录与任务目录展开为当前安装位置和实际绝对路径：

```text
python <Skill目录>/scripts/director_workbench.py prepare --root <当前任务绝对目录>
python <Skill目录>/scripts/director_workbench.py serve --root <当前任务绝对目录> --port 0
python <Skill目录>/scripts/director_workbench.py inspect --root <当前任务绝对目录>
```

`prepare`生成HTML并保留被替换的旧HTML；`serve`仅监听本机，输出实际可用URL。端口0自动选择可用端口，不复制其他电脑的地址。助手保留服务运行会话，用户还在审稿时保持服务可用；不向用户交付已经停止的临时预览地址。续作先检测既有URL和任务绑定，可用就复用，不为每次改字另开一个服务。

在支持`open_in_codex`的环境里，使用工具实际打开返回的URL，目标类型`browser`、`placement="right"`；不是打开HTML源码文件，也不是把Markdown代码贴进右侧。其他助手使用自己的HTML预览或浏览器能力。若环境确实没有右侧预览能力，提供可打开的HTML预览并如实说明，不宣称已在右侧展示。最终回复给可用工作台入口。

## 互动与状态

正文与阅读版本绑定。用户点“采纳文案”时保存该正文的摘要及不可变文本快照，改稿后恢复待确认。没有正文就显示“待写文案”，禁用采纳，不把采纳选题算作认可正文。每个选题支持选用、已拍和备注；拍摄标记的来源是用户自行标记，仍与原片核验、剪辑完成和发布回执分开。允许撤销选择并保留操作记录。

用户点击与备注应持久化到本机文件，助手能直接回读；单纯浏览器localStorage不足以成为默认交接方式。处理“我改好了”“已采纳”“拍完了”之前重新读取状态与对应正文，不要求用户复制状态。页面保存不自动启动写稿、剪辑或发布；按用户当前任务和真实内容推进。

## 验证

从实际URL检查标题、选题条数、原顺序、正文可读性及窄窗口布局。验证搜索和切换；选用、备注、采纳、已拍、刷新保持用隔离数据测试，不在真实业务记录里伪造用户决定。验证无正文不能采纳、改稿不继承采纳、旧窗口不能覆盖新意见、文案路径不越过任务。最后打开正式页面并回读实际数据；报告实际完成范围，不把技术检查当作用户认可。

## 后续任务

读取真实选择与备注来确定待办；只有当前用户的动作或明确聊天指令才产生采纳/拍摄状态。新任务只需更新岗位工作台的当前内容绑定，保留旧项目和旧状态。记录本次采用范围与结果，用户未发生后续任务前不提前宣称已验证未来效果。
